From a failed build to the runbook step.

A small on-call triage tool for CI failures. An MCP server exposes four tools, a Hugging Face zero-shot model labels each error line, and a client calls them in order to print the category and what to do next.

How it works

A small MCP server and a client that calls it in a fixed order.

1

An MCP server

Four tools over stdio: get_error_lines, search_logs, classify_line and lookup_runbook.

2

A zero-shot classifier

A DistilBERT MNLI model on PyTorch labels each error line against five plain-language descriptions. No fine-tuning.

3

A fixed sequence

The client starts the server, pulls the error lines, classifies each, and prints the category with its runbook step.

Run it

Python 3.12. Use an arm64 Python on Apple silicon, since an x86_64 Python resolves to an old torch that transformers rejects.

python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m triage.agent
.venv/bin/python -m pytest -q

The first run downloads the model from Hugging Face.

What this does not do
  • No LLM API call. The orchestration is a fixed sequence of tool calls, not a model choosing tools. Swapping in Claude tool use against the same server is the stated next step and has not been built.
  • No fine-tuning, and accuracy is checked only on the 5-line sample log, which is synthetic.
  • This page does not run the model. The labels shown are from the README, not computed here.
